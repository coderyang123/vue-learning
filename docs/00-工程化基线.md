# 00 · 工程化基线

配套示例：`../examples/01-template-syntax`

## 1. workspace 结构

```
vue-learning/
├── package.json          # 根：只做脚本编排，无业务依赖
├── pnpm-workspace.yaml   # 声明 examples/* 为成员
├── .npmrc
├── docs/                 # 教程正文
└── examples/
    ├── 01-template-syntax/   # 独立 Vite 工程，自带 package.json
    └── ...
```

每个 `examples/*` 都是独立工程，可单独 `cd examples/01-template-syntax && pnpm install && pnpm dev`。在仓库根执行 `pnpm install` 一次装好全部成员。

## 2. 命令

| 命令 | 作用 |
| --- | --- |
| `pnpm install` | 安装所有成员依赖 |
| `pnpm dev` | 并行启动所有示例的 dev server |
| `pnpm lint` | ESLint + Prettier 格式检查 |
| `pnpm typecheck` | `vue-tsc` 类型检查 |
| `pnpm build` | 类型检查 + 生产构建 |
| `pnpm --filter @example/01-template-syntax dev` | 只跑某一个成员 |

## 3. 三条流水线

| 命令 | 底层 | 卡住什么 |
| --- | --- | --- |
| `pnpm lint` | ESLint 9 flat config + `eslint-plugin-vue` + `typescript-eslint` | 写法不规范、误用 Vue 规则 |
| `pnpm typecheck` | `vue-tsc -b` | props 类型不匹配、模板引用不存在的变量 |
| `pnpm build` | `vue-tsc -b && vite build` | 类型不过不打包 |

`vue-tsc -b` 走 project references 增量编译（`tsconfig.json` 引用 `.app.json` / `.node.json`），只重编改动过的部分。

## 4. 路径别名（两侧都要配）

```ts
// vite.config.ts —— 打包器认这个
resolve: { alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) } },
```

```jsonc
// tsconfig.app.json —— 类型检查器认这个（paths 相对本文件解析）
{ "compilerOptions": { "paths": { "@/*": ["./src/*"] } } }
```

只配一边会报错：只配 Vite → `vue-tsc` 找不到模块；只配 TS → dev/build 运行时报错。

## 5. ESLint 配置

```js
export default defineConfigWithVueTs(
  { name: 'app/ignores', ignores: [...] },
  js.configs.recommended,                    // 通用 JS 规则
  ...pluginVue.configs['flat/recommended'],  // Vue SFC 规则
  vueTsConfigs.recommended,                  // TS 规则
  { name: 'app/rules', rules: { ... } },     // 项目自定义
  prettier,                                  // 必须最后
)
```

`prettier` 放最后：它会关掉 ESLint 里所有纯格式规则（含 ESLint 自带的 `semi`），避免与 Prettier 打架。

## 6. 代码风格分工

| 关注点 | 归谁 | 配在哪 |
| --- | --- | --- |
| 分号、引号、缩进、换行、尾逗号 | Prettier | `.prettierrc.json` → `"semi": true` |
| 箭头函数 vs `function` 声明 | ESLint | `func-style` |
| 具名函数必须标注返回类型 | ESLint | `explicit-function-return-type` |

```js
// eslint.config.js
'func-style': ['error', 'expression', { allowArrowFunctions: true }],
'@typescript-eslint/explicit-function-return-type': ['error', { allowExpressions: true }],
'@typescript-eslint/explicit-module-boundary-types': 'error',
```

按文件类型分层：

| 文件 | 规则 | 原因 |
| --- | --- | --- |
| `**/*.vue` | 强制箭头函数 | 组件内统一心智模型 |
| `**/*.ts` | 允许 `export function` | 与 VueUse / Pinia / Vue 核心惯例一致 |

规则行为：

| 写法 | 结果 |
| --- | --- |
| `const f = (a: number): T => {}` | ✅ |
| `const f = (a: number) => {}` | ❌ 缺返回类型（具名函数强制标注） |
| `[1, 2].filter((n) => n > 1)` | ✅ 内联回调可省略 |
| `export function f(): T {}`（`.ts` 里） | ✅ |

**分隔符**：类型位置（`type` / `interface` / `defineProps<T>()`）成员用 `;`，运行时对象字面量用 `,`。Prettier 统一输出 `;`。

## 7. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| `pnpm run` 卡住不返回 | pnpm 在 run 前会联网校验依赖。根目录 `.npmrc` 已设 `verify-deps-before-run=false` |
| `prettier --check` 报格式错 | WebStorm 自带格式化器不读 `.prettierrc.json`。装 Prettier 插件并指定配置文件路径 |
| `vue-tsc` 报「找不到模块」 | 别名只在 Vite 配了，`tsconfig` 的 `paths` 没配 |
| 改完 `.vue` 文件类型检查很快 | `-b` 增量编译，只重编改动的项目 |
