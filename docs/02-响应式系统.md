## §1 语法课

### 2.1 ① `ref` 与模板自动解包

> ▶️ **运行示例**：[打开 2.1 ① ref 与模板自动解包](http://localhost:5172/#/demos/2-1)
> · 源码：[`src/demos/DemoRef.vue`](../examples/02-reactivity/src/demos/DemoRef.vue)

```vue
<script setup lang="ts">
  import {ref} from 'vue';

  const count = ref(0);
  const state = ref({label: '嵌套对象'});
</script>

<template>
  <!-- 模板里：ref 会自动解包，直接写变量名 -->
  <p>{{ count }} / {{ state.label }}</p>

  <button type="button" @click="count++">count +1</button>
</template>
```

**作用**：`ref` 把一个值包成对象（内部就是 `{ value: 原始值 }`），Vue 劫持了这个对象的 `value`
属性——读的时候记下「谁在读」，写的时候通知「该更新了」。模板编译时会把顶层的 `count` 自动改写成
`count.value`，所以模板里**不用**写 `.value`。

**脚本里必须写 `.value`**：

```ts
count.value++;        // ✅ 脚本里
count++;              // ❌ 脚本里是给普通变量赋值，ref 没变
```

```vue
{{ count }}           // ✅ 模板里，自动解包
{{ count.value }}     // ❌ 模板里再解包一次 → undefined
```

**用在哪**：§3.2 实验一（`ref` 与 `reactive` 的写法对照）。

> 对象型的 `ref` 是**深层**的：`state.value.label` 改了，界面照样更新，因为 `ref`
> 内部会把对象再包一层响应式代理（§1.2）。

### 2.2 ② `reactive` 与 Proxy

> ▶️ **运行示例**：[打开 2.2 ② reactive 与 Proxy](http://localhost:5172/#/demos/2-2)
> · 源码：[`src/demos/DemoReactive.vue`](../examples/02-reactivity/src/demos/DemoReactive.vue)

```ts
import {reactive} from 'vue';

const state = reactive({count: 0, profile: {name: '三'}});

state.count++;                 // 一级属性
state.profile.name = '张';     // 二级属性
state.extra = '新加的字段';    // 新增属性
```

**作用**：`reactive` 用 `Proxy` 代理整个对象。 `get` 的时候记下「谁读了哪个属性」，`set`
的时候通知这些「读者」更新。嵌套对象在读取时会被**自动再代理一层**，所以改到多深都能被感知——这就是「深层响应式」。

`Proxy` 还能拦截「新增属性」的操作，所以 `state.extra = '...'` 一样是响应式的。

**用在哪**：§3.2 实验一。

两条必须记住的规则：

1. `reactive` 的返回值**不能整个替换掉**。`state = { count: 0 }`
   只是给局部变量重新赋值，代理还在原来的对象上，界面不会更新。要整体换，得用 `ref`。
2. `reactive` 的属性**不能解构**。`const { count } = state` 拿到的是普通数字，丢响应性（→ §1.3）。

### 2.3 ③ `toRef` / `toRefs` / `toRaw` / `unref`

> ▶️ **运行示例**：[打开 2.3 ③ toRef / toRefs / toRaw / unref](http://localhost:5172/#/demos/2-3)
> · 源码：[`src/demos/DemoToRef.vue`](../examples/02-reactivity/src/demos/DemoToRef.vue)

```ts
import {reactive, toRaw, toRef, toRefs, unref} from 'vue';

const state = reactive({count: 0});

// ① 解构：丢响应性 —— count 变成普通数字
const {count} = state;

// ② toRefs：每个字段都包成 ref，写它等于写原对象
const {count: countRef} = toRefs(state);
countRef.value = 1;            // state.count 也变成了 1

// ③ toRef：单个字段要保持响应性时用
const singleRef = toRef(state, 'count');

// ④ unref：ref 就取 .value，不是 ref 就原样返回
const n = unref(countRef);     // 0
const m = unref(42);           // 42

// ⑤ toRaw：拿回最初那个原始对象（绕过代理）
const raw = toRaw(state);      // 原始对象，不是代理
```

**作用**：响应性建立在 **Proxy**
上。解构时发生的是一次普通的「读」，读出来的是当时的值——一个和 Proxy 无关的普通数字，从此再也不会更新。

`toRefs` 则是把每个属性包成一个 `ObjectRefImpl`：读它的 `.value` 时走 Proxy 的
`get`（记依赖），写它的 `.value` 时走 Proxy 的 `set`（触发依赖）。

**用在哪**：§3.2 实验二（解构 vs `toRefs` 并排对照）。

修复「解构丢响应性」有两条路：

1. **不解构**：模板里直接写 `state.count`，脚本里写 `state.count`。
2. **用 `toRefs` / `toRef`** 拆出来，继续享受解构的写法。

### 2.4 ④ `computed` 的惰性求值与缓存

> ▶️ **运行示例**：[打开 2.4 ④ computed 的惰性求值与缓存](http://localhost:5172/#/demos/2-4)
> · 源码：[`src/demos/DemoComputedCache.vue`](../examples/02-reactivity/src/demos/DemoComputedCache.vue)

```ts
import {computed, ref} from 'vue';

const count = ref(0);

const doubled = computed(() => count.value * 2);
```

**作用**：`computed` 是一个**带缓存的惰性求值**：

- **惰性**：没人读 `doubled.value`，getter 就一次都不会跑。
- **缓存**：读过一次之后，只要依赖（这里是 `count`）没变，再读就返回上次的结果，getter 不重跑。

`computed`
内部会记录 getter 读过的所有响应式数据作为依赖。依赖变了 → 缓存作废 → 下次读取时重新计算。

**用在哪**：§3.2 实验三（`computed` vs 普通函数的「实算次数」对照）。

### 2.5 ⑤ 可写 `computed`（get / set）

> ▶️ **运行示例**：[打开 2.5 ⑤ 可写 computed（get / set）](http://localhost:5172/#/demos/2-5)
> · 源码：[`src/demos/DemoWritableComputed.vue`](../examples/02-reactivity/src/demos/DemoWritableComputed.vue)

```ts
import {computed, ref} from 'vue';

const firstName = ref('三');
const lastName = ref('张');

const fullName = computed({
    get: () => `${firstName.value}${lastName.value}`,
    set: (value: string) => {
        firstName.value = value.slice(0, 1);
        lastName.value = value.slice(1);
    },
});
```

**作用**：默认的 `computed` 是**只读**的（`WritableComputedRef`
才有 setter）。传对象形式就能给它加上 `set`，此时 `fullName.value = '张三丰'`
会调用 setter，由你自己决定这个新值怎么拆回源数据。

一句话记忆：**读是拼名字，写是拆名字**。

**用在哪**：§3.2 的可写 `computed` 面板。

### 2.6 ⑥ `watch` 的三个选项

> ▶️ **运行示例**：[打开 2.6 ⑥ watch 的三个选项](http://localhost:5172/#/demos/2-6)
> · 源码：[`src/demos/DemoWatch.vue`](../examples/02-reactivity/src/demos/DemoWatch.vue)

```ts
import {ref, watch} from 'vue';

const count = ref(0);

// 基本用法：值变了才触发
watch(count, (newValue, oldValue) => {
    console.log(newValue, oldValue);
});

// ① immediate：创建时就先跑一次
watch(count, (newValue) => {
}, {immediate: true});

// ② deep：深度侦听对象内部
watch(state, (newValue) => {
}, {deep: true});

// ③ flush：决定回调什么时候跑
watch(count, (newValue) => {
}, {flush: 'post'});
```

**作用**：`watch` 是**显式**的侦听器：你写明监听谁，它就盯谁。

| 选项        | 默认值  | 作用                                                               |
|-------------|---------|--------------------------------------------------------------------|
| `immediate` | `false` | 创建 watcher 时立刻执行一次回调（`oldValue` 是 `undefined`）       |
| `deep`      | `false` | 深度侦听：对象内部任何一层变了都触发                               |
| `flush`     | `'pre'` | 回调的时机：`'pre'` 组件更新前、`'post'` 组件更新后、`'sync'` 同步 |

**用在哪**：§3.2 实验四，以及 §1.8 的副作用清理。

### 2.7 ⑦ `watchEffect` 与自动依赖收集

> ▶️ **运行示例**：[打开 2.7 ⑦ watchEffect 与自动依赖收集](http://localhost:5172/#/demos/2-7)
> · 源码：[`src/demos/DemoWatchEffect.vue`](../examples/02-reactivity/src/demos/DemoWatchEffect.vue)

```ts
import {ref, watchEffect} from 'vue';

const count = ref(0);

// 不写监听谁：函数体里读了什么，就自动监听什么
watchEffect(() => {
    console.log(count.value);
});
```

**作用**：`watchEffect`
立刻执行一次，并在执行过程中**自动收集**它读到的所有响应式数据。这些数据变了，它就重跑。

它和 `watch` 的差别：

|            | `watch`                      | `watchEffect`                    |
|------------|------------------------------|----------------------------------|
| 监听谁     | 写明（第一个参数）           | 自动（函数体里读到的）           |
| 第一次执行 | 不执行（`immediate` 才执行） | **立刻执行一次**                 |
| 依赖变化   | 按写明的源来定               | 按读到的来定，读到新的就多盯一个 |
| 拿旧值     | 有（`oldValue`）             | 没有（要旧值就用 `watch`）       |

**用在哪**：§3.2 实验四（`watch` 与 `watchEffect` 的触发次数对照）。

> 一个容易踩的坑：在 `watchEffect` 的函数体里**写**一个
> `ref`，等于让这个副作用依赖自己写的东西，容易形成自触发。需要在副作用里记录内容，用普通变量或普通数组更稳。

### 2.8 ⑧ `onCleanup` 副作用清理

> ▶️ **运行示例**：[打开 2.8 ⑧ onCleanup 副作用清理](http://localhost:5172/#/demos/2-8)
> · 源码：[`src/demos/DemoOnCleanup.vue`](../examples/02-reactivity/src/demos/DemoOnCleanup.vue)

```ts
import {onWatcherCleanup, ref, watch} from 'vue';

const keyword = ref('');

// 写法一：watch 的第 4 个参数
watch(keyword, (newValue, oldValue, onCleanup) => {
    const timer = setTimeout(() => {
        console.log('请求回来了', newValue);
    }, 800);

    onCleanup(() => {
        clearTimeout(timer); // 旧请求作废
    });
});

// 写法二：3.5+ 的 onWatcherCleanup（必须在回调里同步调用）
watch(keyword, (newValue) => {
    onWatcherCleanup(() => {
        console.log('旧请求作废');
    });
});
```

**作用**：watcher 每次重跑之前，Vue 会先调用**上一次的清理函数**。 `onCleanup`
就是在那个时机做善后：取消没发完的请求、关掉定时器、解绑事件。

没有它就会出现典型的竞态：旧请求晚回来，把新请求的结果覆盖掉。

**用在哪**：§1.6 的 `watch` 回调里做「请求 + 取消」。

### 2.9 ⑨ 调度机制与 `nextTick`

> ▶️ **运行示例**：[打开 2.9 ⑨ 调度机制与 nextTick](http://localhost:5172/#/demos/2-9)
> · 源码：[`src/demos/DemoNextTick.vue`](../examples/02-reactivity/src/demos/DemoNextTick.vue)

```ts
import {nextTick, ref} from 'vue';

const count = ref(0);

const bump = async () => {
    count.value++;
    count.value++;
    count.value++;

    // 同步代码到这里结束，界面还没更新
    await nextTick();
    // 现在 DOM 已经是新值了
};
```

**作用**：Vue 把「组件更新」排进一个**微任务队列**，同一轮里的多次修改会**合并成一次**更新。所以连续
`count.value++` 三次，界面只重渲染一次。

`nextTick` 返回一个 Promise，等的是「这一轮 DOM 更新完成」。

| 想做的事                    | 用什么                          |
|-----------------------------|---------------------------------|
| 改完数据后立刻读 DOM        | `await nextTick()`              |
| 数据变了就做副作用          | `watch` / `watchEffect`         |
| 数据变了要等 DOM 更新完再做 | `watch(..., { flush: 'post' })` |

**用在哪**：§3.2 的 `watch` / `watchEffect` 面板。

### 2.10 ⑩ `shallowRef` / `shallowReactive` / `markRaw`

> ▶️
> **运行示例**：[打开 2.10 ⑩ shallowRef / shallowReactive / markRaw](http://localhost:5172/#/demos/2-10)
> · 源码：[`src/demos/DemoShallow.vue`](../examples/02-reactivity/src/demos/DemoShallow.vue)

```ts
import {markRaw, reactive, shallowReactive, shallowRef} from 'vue';

// ① shallowRef：只有 .value 本身是响应式的
const shallow = shallowRef({count: 0});
shallow.value.count++;             // ❌ 不触发更新（第一层以下不跟）
shallow.value = {count: 1};     // ✅ 触发更新（换了引用）

// ② shallowReactive：只有第一层属性是响应式的
const shallowState = shallowReactive({count: 0});
shallowState.count++;             // ❌ 不触发更新
shallowState.count = 1;           // ✅ 触发更新

// ③ markRaw：标记「这个对象永远不要被代理」
const raw = markRaw({hits: 0});
const box = reactive({raw});
box.raw.hits++;                   // ❌ 不触发更新
```

**作用**：深层响应式是有成本的——每读一层都要建代理、记依赖。当数据很大、或者你**明确知道**改深层不会影响界面时，浅层响应式更划算。

`markRaw`
则是反向操作：给对象打一个「别代理我」的标记。典型用途是放第三方的大对象、类实例（`Map`、`Date`、图表实例等）。

**用在哪**：§3.2 的 `shallowRef` 对照面板。

### 2.11 ⑪ `useTemplateRef`

> ▶️ **运行示例**：[打开 2.11 ⑪ useTemplateRef](http://localhost:5172/#/demos/2-11)
> · 源码：[`src/demos/DemoTemplateRef.vue`](../examples/02-reactivity/src/demos/DemoTemplateRef.vue)

```vue
<script setup lang="ts">
  import {ref, useTemplateRef} from 'vue';

  const inputRef = useTemplateRef<HTMLInputElement>('keyword');
</script>

<template>
  <!-- ref="keyword" 里的字符串，和 useTemplateRef('keyword') 的参数对上 -->
  <input ref="keyword"/>
  <button type="button" @click="inputRef?.focus()">聚焦输入框</button>
</template>
```

**作用**：Vue 3.5 新增的模板 ref 写法。 `useTemplateRef('keyword')` 返回一个
`Readonly<ShallowRef<T | null>>`，模板里的 `ref="keyword"`
会自动填进它——**靠字符串 key 对应**，不靠变量名。

对比第 01 章的写法（⑭ `ref`）：

```ts
// 第 01 章：变量名要写在模板的 ref 属性上
const inputEl = ref<HTMLInputElement | null>(null);
```

```vue
<!-- 3.5：ref 属性只写字符串 key -->
<input ref="keyword"/>
```

因为返回的是**只读**的 `shallowRef`，你不能 `inputRef.value = el` 手动赋值，要操作 DOM 就通过
`inputRef.value` 拿到元素后调它的方法。

**用在哪**：§1.9 的 `nextTick` 演示（读 DOM 里的真实值）。

## §2 响应式机制图

### 2.2.1 依赖收集与触发

```
        ① 读取                          ② 记账
   ┌──────────────────┐         ┌──────────────────────────────┐
   │  state.count     │         │ depsMap                     │
   │  ↑               │         │  原始对象 → 'count' → {effect}│
   │ Proxy 的 get 拦截  │────────▶│  （谁读过我，记在谁名下）      │
   └──────────────────┘         └──────────────┬───────────────┘
                                               │
                                               │ 触发时取出这个 Set
                                               ▼
   ┌──────────────────┐         ┌──────────────────────────────┐
   │  state.count = 1 │         │ 重新执行 effect（重算 + 重渲染）│
   │  ↑               │         └──────────────────────────────┘
   │ Proxy 的 set 拦截 │                     │
   └──────────────────┘                     ▼
                                          界面更新
```

读的时候**登记**（track），写的时候**通知**（trigger）——这两步就是 `src/reactive.ts`
里手写的全部内容。

### 2.2.2 一次修改的完整流程

```
 同步代码                微任务队列（flushJobs）              浏览器绘制
 ─────────            ─────────────────────────          ────────────
 count.value++   ──▶   组件更新 job 入队
 count.value++        watch 回调（flush: 'pre'）        ──▶  DOM 更新
 count.value++        watch 回调（flush: 'post'）
                     ──▶  nextTick 回调（DOM 已是新值）
```

同一轮里的三次修改被合并成**一次**组件更新，所以「连续改三次，界面只更新一次」。

## §3 代码精读

### 3.1 `src/reactive.ts`

Vue 的响应式再复杂，骨架也是这张图：**读的时候记账，写的时候通知**。这个文件就是把这套机制手写一遍——代码很短，但每一行都对得上
§2.2.1 那张图。

```ts
/**
 * 手写的迷你响应式系统：Proxy + Reflect + 依赖收集 / 依赖触发。
 *
 * Vue 真实的实现复杂得多（依赖去重、版本号 bump、调度器、只读劫持……），
 * 但骨架就是这四步：
 *
 *   1. 读属性时，把「当前正在跑的副作用」记到这个属性名下（收集依赖）
 *   2. 写属性时，把记在这个属性名下的副作用重新执行一遍（触发依赖）
 *
 * 本文件只做教学演示，不追求性能与完备性。
 */
```

#### ① 副作用与依赖表

```ts
/** 一个副作用函数：它依赖的数据变了，就重新跑一遍 */
export type Effect = () => void;

/**
 * 依赖表：目标对象 → 属性名 → 依赖这个属性的所有副作用。
 *
 * 用 WeakMap 是因为它的键是对象，源对象被回收时整张表可以一起被回收。
 */
const depsMap = new WeakMap<object, Map<PropertyKey, Set<Effect>>>();

/** 当前正在收集依赖的副作用；为 undefined 表示「现在不在收集」 */
let activeEffect: Effect | undefined;

/** 只把「对象」当成可代理的目标，原始值不代理 */
const isObject = (value: unknown): value is Record<PropertyKey, unknown> =>
    typeof value === 'object' && value !== null;
```

三个变量就是这套系统的全部状态：

- `Effect`：副作用的类型——一个没有参数、没有返回值的函数（「重算一遍」「重渲染一遍」）。
- `depsMap`：依赖表。键是**原始对象**（不是代理），值是「属性名 → 副作用集合」。
- `activeEffect`：当前正在跑的副作用。收集依赖时，就是把它登记到某个属性名下。

> 依赖表的键用的是**原始对象**：`get` 拦截器里拿到的 `target`
> 就是原始对象，无论你从哪个代理上读到的，登记的永远是同一个 key——所以触发时才找得到人。

#### ② `track`：读的时候记账

```ts
/**
 * 读取属性时调用：把 activeEffect 登记到这个属性名下。
 *
 * 依赖关系是「哪个副作用读过哪个对象的哪个属性」，粒度到属性一级。
 */
export const track = (target: object, key: PropertyKey): void => {
        // 不在任何副作用里读属性（比如初始化时直接读），就没有依赖要收集
        if (!activeEffect) return;

        let deps = depsMap.get(target);
        if (!deps) {
            deps = new Map();
            depsMap.set(target, deps);
        }

        let effects = deps.get(key);
        if (!effects) {
            effects = new Set();
            deps.set(key, effects);
        }

        effects.add(activeEffect);
    };
```

四步：取出这张对象的依赖表 → 没有就建 → 取出这个属性的副作用集合 → 没有就建 → 把当前副作用加进去。

`Set` 而不是 `Array`：同一个副作用重复读同一个属性，集合里也只有一份。

#### ③ `trigger`：写的时候通知

```ts
/**
 * 写入属性时调用：把登记在这个属性名下的副作用重新执行一遍。
 */
export const trigger = (target: object, key: PropertyKey): void => {
        const effects = depsMap.get(target)?.get(key);
        if (!effects) return;

        // 复制一份再遍历：副作用重新执行时可能再次改动依赖表，边遍历边改会出问题
        for (const effect of [...effects]) {
            effect();
        }
    };
```

`[...effects]`
是一次快照。副作用重跑时会重新收集依赖，如果直接遍历原集合，遍历过程里集合被改动，结果就不可预期了。

#### ④ `effect`：跑起来，顺便把依赖记上

```ts
/**
 * 执行 fn，并把它读到的所有属性登记成依赖。
 *
 * 返回的 runner 可以手动再跑一次，用来观察「依赖变了 → 副作用重跑」。
 */
export const effect = (fn: Effect): Effect => {
        const runner = (): void => {
            // 把自己设成「当前副作用」，fn 里读到的属性就都会记到它名下
            activeEffect = runner;
            fn();
            activeEffect = undefined;
        };

        runner();
        return runner;
    };
```

`effect` 的套路是：**先把自己亮出来，再执行函数**。执行期间读到的每一个属性，都会顺着 `activeEffect`
登记到 `depsMap` 里。

> Vue 真实的 `effect` 更讲究：执行前会先把上一次的依赖清掉，并且用的是 `try/finally` 保证
> `activeEffect` 一定被还原。这里为了讲清楚主线，做了简化。

#### ⑤ `createReactive`：把记账和通知接到 Proxy 上

```ts
/**
 * 创建一个响应式代理：读的时候收集依赖，写的时候触发副作用。
 */
export const createReactive = <T extends object>(target: T): T =>
        new Proxy(target, {
            get(target, key, receiver) {
                // 读：先记账
                track(target, key);

                const value = Reflect.get(target, key, receiver);

                // 嵌套对象再包一层，这样改深层属性也能触发
                return isObject(value) ? createReactive(value) : value;
            },

            set(target, key, value, receiver) {
                // 写：先让 Reflect 真正写进去
                const result = Reflect.set(target, key, value, receiver);

                // 再通知依赖这个属性的副作用
                trigger(target, key);
                return result;
            },
        });
```

对照 §2.2.1 的图：

- `get` 拦截器 = **读的时候记账**（`track`）。
- `set` 拦截器 = **写的时候通知**（`trigger`）。
- `Reflect.get` / `Reflect.set`
  = 把「真正的读写」交回给原始对象，免得自己重写一遍对象语义（getter、setter、属性描述符…）。

最后那行 `isObject(value) ? createReactive(value) : value`
就是**深层响应式**的来源：读到嵌套对象时再包一层代理，于是 `state.profile.name`
的每一层都有代理在记账。

### 3.2 `src/App.vue`

主示例是四组对照实验。每一组只改一个变量，把「差别在哪」逼出来。

```ts
import {computed, reactive, ref, toRefs, watch, watchEffect} from 'vue';
import {createReactive, effect} from '@/reactive';
import type {CounterState} from '@/types';

// ── 实验一：ref vs reactive ──────────────────────────────────────────
const refCount = ref(0);
const reactiveState = reactive<CounterState>({count: 0, label: 'reactive 对象'});

// ── 实验二：解构丢响应性 vs toRefs ──────────────────────────────────
const plainState = reactive({count: 0});
const {count: brokenCount} = plainState; // 解构：拿到的是一次性的快照
const linkedState = reactive({count: 0});
const {count: linkedCount} = toRefs(linkedState); // toRefs：拿到的还是 ref

// ── 实验三：computed vs 普通函数 ────────────────────────────────────
const tasks = ref([{id: 1, title: '读 Vue 3 响应式源码', done: true}]);
let computedRuns = 0;
let methodRuns = 0;
const renderTick = ref(0);

const remaining = computed((): number => {
    computedRuns++;
    return tasks.value.filter((task) => !task.done).length;
});

const remainingByMethod = (): number => {
    methodRuns++;
    return tasks.value.filter((task) => !task.done).length;
};
```

三处值得停下来看：

1. `const { count: brokenCount } = plainState;`（②）——这一行就是「解构丢响应性」的现场。
   `brokenCount` 是一个普通数字，后面 `plainState.count++` 再怎么改，它都不会变。
2. `const { count: linkedCount } = toRefs(linkedState);`（③）——同一个解构写法，换成
   `toRefs`，拿到的还是 `ref`，写它等于写 `linkedState.count`。
3. `computedRuns++` 为什么用普通变量（⑤）——因为在 `computed` 的 getter 里写 `ref`
   会自触发递归，Vue 会直接报 Maximum recursive updates exceeded（§1.4）。

```ts
// ── 实验四：watch vs watchEffect ────────────────────────────────────
const probe = ref(0);

// watch 的回调不参与依赖收集，回调里写普通变量是安全的
let watchRuns = 0;

// watchEffect 的函数体本身就是被收集依赖的地方，
// 所以这里只能用普通变量：写成 ref 会让副作用依赖自己写的那个 ref，形成自触发
let effectRuns = 0;
let effectProbe = 0;

watch(probe, (): void => {
    watchRuns++;
});

watchEffect((): void => {
    effectRuns++;
    effectProbe = probe.value;
});
```

这一段是本章最容易被忽略、也最容易踩坑的地方：

- `watch` 的**回调**不参与依赖收集，所以在回调里写 `ref` 是安全的。
- `watchEffect` 的**函数体**就是被收集依赖的地方，在里面写 `ref`
  等于让这个副作用依赖自己写的东西，容易自触发。

所以两个计数器都用了普通变量。代价是：普通变量本身不会触发重渲染，界面能更新是因为 `probe`
变了——模板里渲染了 `probe`，重渲染时顺带读到了新值。

```ts
// ── 手写 createReactive：依赖收集 / 触发是真的在跑 ──────────────────
const manual = createReactive({count: 0, nested: {level: 0}});
const manualLog = ref<string[]>([]);

effect((): void => {
    manualLog.value.unshift(`[effect] count=${manual.count} level=${manual.nested.level}`);
});
```

这一段把 §3.1 的手写实现接进了真实界面：点按钮 → 代理的 `set` 拦截器 → `trigger` → 依赖表里取出
`effect` → 重新执行 → 日志多一行。

注意 `manual.count` 和 `manual.nested.level` **都在** `effect`
里被读到，所以它们都是依赖——改任何一个，`effect` 都会重跑。

```ts
// 脚本里读 ref 必须写 .value，模板里则不用写
const readRefInScript = (): number => refCount.value;

const bumpRef = (): void => {
    refCount.value++;
};

const bumpReactive = (): void => {
    reactiveState.count++;
};

const bumpBoth = (): void => {
    plainState.count++;
    linkedState.count++;
};

const triggerRerender = (): void => {
    renderTick.value++;
};

const bumpProbe = (): void => {
    probe.value++;
};

const bumpManual = (): void => {
    manual.count++;
    manual.nested.level++;
};
```

`bumpBoth` 是实验二的关键：一次点击同时改两个对象，左边的 `brokenCount` 不动，右边的 `linkedCount`
跟着变——差别一眼可见。
