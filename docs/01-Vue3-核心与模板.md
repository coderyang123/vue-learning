## §1 语法课

### 1.1 ① SFC 结构

SFC = Single File Component（单文件组件）：**一个 `.vue`
文件就是一个组件**，模板、逻辑、样式写在一起。

```vue
<template>...</template>
<script setup lang="ts">...</script>
<style scoped>...</style>
```

- `<script setup>` 的顶层变量、导入的组件，模板里直接可用（见 ②）。
- `lang="ts"` 让模板里的表达式也接受类型检查。
- `<style scoped>` 把样式限制在本组件内；去掉 `scoped` 就是全局样式。
- `.vue` 文件要靠 Vite 编译，浏览器打不开。

### 1.2 ② 顶层变量自动暴露

```vue
<script setup lang="ts">
  import {ref} from 'vue';

  const count = ref(0);
</script>

<template>
  <button @click="count++">{{ count }}</button>
</template>
```

`<script setup>` 的顶层变量、函数、导入的组件在模板里直接可用，不用 `return`，不用 `components: {}`
注册。

### 1.3 ③ 插值 `{{ }}`

> ▶️ **运行示例**：[打开 1.3 ③ 插值 {{ }}](http://localhost:5171/#/demos/1-3)
> · 源码：[`src/demos/DemoInterpolation.vue`](../examples/01-template-syntax/src/demos/DemoInterpolation.vue)

```vue
<span>{{ task.title }}</span>
<span>{{ tasks.length }} 项</span>
```

渲染表达式的结果，自动转义 HTML。

### 1.4 ④ `v-bind` / `:`

> ▶️ **运行示例**：[打开 1.4 ④ v-bind / :](http://localhost:5171/#/demos/1-4)
> · 源码：[`src/demos/DemoVBind.vue`](../examples/01-template-syntax/src/demos/DemoVBind.vue)

```vue
<img :src="url"/>
<div :class="{ active: isActive }"></div>
<div :class="['base', isActive ? 'active' : '']"></div>
<div :style="{ color: color }"></div>
<button :disabled="isLoading">提交</button>
```

绑定属性。`:class` / `:style` 支持对象与数组语法。

绑假值时属性会被**整个去掉**：`:disabled="false"` 等于「没有 disabled」，不是 `disabled="false"`。

`:value`
把数据**灌进**控件：数据变了控件跟着变，反过来不成立——你在输入框里打的字不会自动改数据。补上「读回来再写回去」就是 ⑥
`v-model`（§1.6）。

> 本节示例里的 `@click` / `@input` 属于下一节的 ⑤
> `v-on`。数据要变只能靠事件触发，所以这一节不可避免会用到它；但除此之外不提前使用后面章节的语法。

### 1.5 ⑤ `v-on` / `@`

> ▶️ **运行示例**：[打开 1.5 ⑤ v-on / @](http://localhost:5171/#/demos/1-5)
> · 源码：[`src/demos/DemoVOn.vue`](../examples/01-template-syntax/src/demos/DemoVOn.vue)

`v-on` = 监听事件并调用处理函数。`@` 是 `v-on:` 的简写。

**最小示例**（节选自配套示例 `src/demos/DemoVOn.vue`）：

```vue
<script setup lang="ts">
  import {ref} from 'vue';

  const log = ref<string[]>([]);

  // 方法引用：@click="handleRef" → 实际调用 handleRef($event)，事件对象自动传入
  const handleRef = (event: Event): void => {
    log.value = [`收到参数：${event.type}`, ...log.value];
  };

  // 括号写法：@click="handleCall()" → 实际调用 handleCall()，不会传事件对象
  const handleCall = (): void => {
    log.value = ['没有参数（括号写法不传事件对象）', ...log.value];
  };

  // 显式传事件：@click="handleExplicit($event)"
  const handleExplicit = (event: Event): void => {
    log.value = [`收到参数：${event.type}`, ...log.value];
  };
</script>

<template>
  <!-- 方法引用：自动把事件对象作为第一个参数传进去 -->
  <button @click="handleRef">@click="handleRef"</button>

  <!-- 内联调用：括号里的参数覆盖，$event 不再自动传入 -->
  <button @click="handleCall()">@click="handleCall()"</button>

  <!-- 显式传事件对象 -->
  <button @click="handleExplicit($event)">@click="handleExplicit($event)"</button>

  <pre>{{ log.join('\n') }}</pre>
</template>
```

处理器的三种写法：

| 写法                              | 实际调用                 | 说明             |
|-----------------------------------|--------------------------|------------------|
| `@click="handleRef"`              | `handleRef($event)`      | 自动传事件对象   |
| `@click="handleCall()"`           | `handleCall()`           | 括号写法不传事件 |
| `@click="handleExplicit($event)"` | `handleExplicit($event)` | 显式传事件       |

修饰符（写在事件名后面，用 `.` 连接）：

| 修饰符                  | 作用                          |
|-------------------------|-------------------------------|
| `.prevent`              | `event.preventDefault()`      |
| `.stop`                 | `event.stopPropagation()`     |
| `.self`                 | 只在点到自身时触发            |
| `.once`                 | 只触发一次                    |
| `.capture` / `.passive` | 捕获阶段 / 承诺不阻止默认行为 |

`.prevent` 在表单上必需：原生提交会刷新页面。

配套示例把 `.prevent`、`.stop`、`.once`、`.self` 都跑了一遍；`.capture` / `.passive`
属于进阶用法，知道有这回事即可。

```vue
<form @submit.prevent="addTask">
  <input @input="onInput"/>
  <button type="submit">添加</button>
</form>
```

`@input` 用来**读**：事件对象里带着控件当前的值，`$event.target.value`
就是输入框里的字。注意这里只读不写回——`draft` 改了不会同步回输入框，那是 ④ `:value` / ⑥ `v-model`
的事。

### 1.6 ⑥ `v-model`

> ▶️ **运行示例**：[打开 1.6 ⑥ v-model](http://localhost:5171/#/demos/1-6)
> · 源码：[`src/demos/DemoVModel.vue`](../examples/01-template-syntax/src/demos/DemoVModel.vue)

`v-model` = **一个值 ↔ 一个可编辑目标**的双向绑定，分两种用法：

- **原生控件**：数据 ↔ DOM 控件
- **自定义组件**：父组件状态 ↔ 子组件状态

#### 1.6.1 原生控件

`v-model` = 数据 ↔ DOM 控件的双向绑定：数据变 → 界面变；界面改 → 数据也变。

**最小示例**（先只看文本框这一种控件）：

```vue
<script setup lang="ts">
  import {ref} from 'vue';

  const name = ref('');
</script>

<template>
  <input v-model="name" placeholder="请输入名字"/>
  <p>你好，{{ name || '（还没输入）' }}</p>
</template>
```

在输入框里打字 → `name` 跟着变 → 下面的文字实时更新；反过来改 `name`，输入框里的字也跟着变。

编译后约等于：

```vue
<input :value="name" @input="name = $event.target.value"/>
```

回头看前两节就明白了：**④ 的 `:value` 负责「写进控件」，⑤ 的 `@input`
负责「从控件读出来」**，两个拼在一起才是
`v-model`。这也是为什么它俩必须成对出现——少了写的那一半，模型就永远跟不上输入框。

**运行时到底做了什么**（Vue 的 `vModelText` 指令）：

| 时机          | 动作                                                            | 方向       |
|---------------|-----------------------------------------------------------------|------------|
| 创建元素时    | 给 DOM 绑 `input` 事件监听：事件触发时读 `el.value` 写回 `name` | DOM → 数据 |
| 挂载 / 更新时 | 把 `name` 的值写进 `el.value`（值一致就不写）                   | 数据 → DOM |

- 监听的是 `input` 事件，**每次按键都会触发**（加 `.lazy` 才改成 `change`）。
- 数据源是 `name` 这个 ref，DOM 只是它的显示层——所以别去直接改 DOM 的 value。
- 中文输入法组字期间的事件会被忽略（源码里的 `e.target.composing`），不会打断输入。

源码位置：`node_modules/@vue/runtime-dom/dist/runtime-dom.cjs.js` → 搜 `vModelText`。

**不同控件绑的不是同一个属性**——Vue 为每类控件实现了独立的指令：

| 控件                                                                         | 指令             | 绑的属性          | 监听的事件                     | 模型值                         |
|------------------------------------------------------------------------------|------------------|-------------------|--------------------------------|--------------------------------|
| `<input type="text">`、`<textarea>`、`<input type="password/email/number…">` | `vModelText`     | `value`           | `input`（`.lazy` 时 `change`） | 文本字符串                     |
| `<input type="checkbox">`                                                    | `vModelCheckbox` | `checked`         | `change`                       | `true` / `false`               |
| `<input type="checkbox">`（多选）                                            | `vModelCheckbox` | `checked`         | `change`                       | 字符串数组                     |
| `<input type="radio">`                                                       | `vModelRadio`    | `checked`         | `change`                       | 被选中那个 radio 的 `value`    |
| `<select>`                                                                   | `vModelSelect`   | option 的选中状态 | `change`                       | 选中项的 `value`（多选是数组） |
| `<input :type="x">`                                                          | `vModelDynamic`  | 运行时再决定      | 运行时再决定                   | 按上面选                       |

每类控件都是「**状态属性 + 对应事件**」的组合，展开后大致是这样：

```vue
<!-- 文本：value + input -->
<input :value="name" @input="name = $event.target.value"/>

<!-- 复选框：checked + change -->
<input type="checkbox" :checked="agreed" @change="agreed = $event.target.checked"/>

<!-- 单选：checked + change，值取 radio 自己的 value -->
<input type="radio" value="easy" :checked="level === 'easy'" @change="level = $event.target.value"/>

<!-- 下拉：value + change -->
<select :value="city" @change="city = $event.target.value">
  <option value="bj">北京</option>
</select>
```

**完整示例**（配套示例 `src/demos/DemoVModel.vue`
就是这五种控件，页面上每个控件下面都跟着它的模型值，可以直接点开看）：

```vue
<script setup lang="ts">
  import {ref} from 'vue';

  const nickname = ref('');          // 文本 → string
  const agreed = ref(false);         // 复选框 → boolean
  const level = ref('normal');       // 单选按钮组 → 选中项的 value
  const city = ref('bj');            // 下拉 → 选中项的 value
  const tags = ref<string[]>([]);    // 多选框 → string[]
</script>

<template>
  <!-- 文本类：绑 value -->
  <input v-model="nickname" placeholder="昵称"/>
  <p>昵称：{{ nickname }}</p>

  <!-- 复选框：绑 checked，模型是 boolean -->
  <label><input type="checkbox" v-model="agreed"/> 同意条款</label>

  <!-- 单选按钮：模型是被选中那个的 value -->
  <label><input type="radio" value="easy" v-model="level"/> 简单</label>
  <label><input type="radio" value="normal" v-model="level"/> 普通</label>

  <!-- 下拉：模型是选中项的 value -->
  <select v-model="city">
    <option value="bj">北京</option>
    <option value="sh">上海</option>
  </select>

  <!-- 多选框：模型是数组，勾一个加一项，取消删一项 -->
  <label><input type="checkbox" value="vue" v-model="tags"/> Vue</label>
  <label><input type="checkbox" value="ts" v-model="tags"/> TypeScript</label>
</template>
```

**修饰符**（写在 `v-model` 后面，用 `.` 连接）：

| 修饰符    | 作用                                          |
|-----------|-----------------------------------------------|
| `.lazy`   | 监听 `change` 而不是 `input`，失焦/回车才同步 |
| `.number` | 自动把输入转成 `number`（转不了就还是字符串） |
| `.trim`   | 自动去掉首尾空格                              |

两个常见扩展：

```vue
<!-- 复选框自定义真假值 -->
<input type="checkbox" v-model="flag" true-value="yes" false-value="no"/>

<!-- 文件上传不支持 v-model，要手动处理 -->
<input type="file" @change="onFileChange"/>
```

#### 1.6.2 自定义组件

组件上的 `v-model` = **父组件状态 ↔ 子组件状态**：

```vue
<!-- 父组件 -->
<TaskFilterBar v-model="filter"/>
```

但它在底层展开成「父传一个 prop + 子 emit 一个事件」，要读懂这行，需要 `defineProps`（⑫）和
`defineEmits`（⑬）——这两节在后面。**完整拆解见 1.17 ⑰「组件上的 `v-model` 与
`defineModel`」**，读完那节再回来看这行。

### 1.7 ⑦ `v-for`

> ▶️ **运行示例**：[打开 1.7 ⑦ v-for](http://localhost:5171/#/demos/1-7)
> · 源码：[`src/demos/DemoVFor.vue`](../examples/01-template-syntax/src/demos/DemoVFor.vue)

```vue
<li v-for="task in visibleTasks">{{ task.title }}</li>
<li v-for="(task, index) in visibleTasks">{{ index }}: {{ task.title }}</li>
```

遍历数组或对象。遍历对象时第一个参数是 **value**，第二个是 **key**：`v-for="(score, name) in scoreboard"`。

> 配套示例里用到了 `:key`（下一节 ⑧ 的内容），这里先按 id 写对；输入框用的 `v-model` 见 ⑥。

> ⚠️ **别把 `v-if` 和 `v-for` 写在同一个元素上**：Vue 3 里 `v-if` **先于** `v-for` 求值（和 Vue
> 2 相反），所以循环变量在 `v-if` 表达式里还不存在——写成 `v-if="task.done"` 运行时会直接报
> `task is not defined`。正确做法是**先过滤出要渲染的数据**，再 `v-for` 渲染（用 `computed`
> 缓存结果的写法见 ⑮ §1.15）。运行示例见 1.7 的「▶️ 运行示例」。

### 1.8 ⑧ `:key`

> ▶️ **运行示例**：[打开 1.8 ⑧ :key](http://localhost:5171/#/demos/1-8)
> · 源码：[`src/demos/DemoVKey.vue`](../examples/01-template-syntax/src/demos/DemoVKey.vue)

```vue
<TaskItem v-for="task in visibleTasks" :key="task.id"/>
```

key 是节点身份标识，diff 时用它判断「同一节点还是新节点」。用稳定唯一的 id，**不要用 index**——列表中间增删时
index会错位，导致组件状态跟错人。

### 1.12 ⑫ `defineProps`

> ▶️ **运行示例**：[打开 1.12 ⑫ defineProps](http://localhost:5171/#/demos/1-12)
> · 源码：[`src/demos/DemoDefineProps.vue`](../examples/01-template-syntax/src/demos/DemoDefineProps.vue)

`props` = 父组件传给子组件的数据，**单向**。

**子组件** `src/components/TaskItem.vue` —— 声明「我要接收一个叫 `task` 的 prop，类型是
`Task`」，并在模板里用它：

```vue
<script setup lang="ts">
  import type {Task} from '@/types';

  const props = defineProps<{
    task: Task;
  }>();
</script>

<template>
  <li class="task" :class="{ 'task--done': props.task.done }">
    <span class="task__title">{{ props.task.title }}</span>
  </li>
</template>
```

模板里通过 `props.task.xxx` 读取 prop 的值。`props` 是 `defineProps()`
的返回值，属于顶层变量，模板里直接可用（②）。

**父组件** `src/App.vue` —— 把值传进去：

```vue
<script setup lang="ts">
  import {ref} from 'vue';
  import TaskItem from '@/components/TaskItem.vue';   // 导入子组件，模板里才能用
  import type {Task} from '@/types';

  const selectedTask = ref<Task>({id: 1, title: '读 Vue 3 响应式源码', done: false});
</script>

<template>
  <TaskItem :task="selectedTask"/>
</template>
```

注意 `:task="selectedTask"` **左右两边不同名**，这是故意的：

| 位置                               | 是什么               | 要求                   |
|------------------------------------|----------------------|------------------------|
| 子组件 `task: Task`                | **prop 名**          | 父组件必须用同名属性传 |
| 父组件 `:task="selectedTask"` 左边 | **prop 名**          | 必须和子组件声明的一致 |
| 父组件 `:task="selectedTask"` 右边 | **父组件自己的变量** | 名字随意               |

左边 `task` 是 prop 名，必须和子组件声明对上；右边 `selectedTask`
是父组件作用域里的变量，爱叫什么叫什么。

运行时 Vue 按**名字**匹配：父组件生成的 props 对象 `{ task: ... }` → 找到子组件声明的 `task`
prop。多传的没声明的属性落到 `$attrs`，必需的 prop 没传会告警。

**props 本身不可修改**——要改就 `emit` 给父组件。（改 prop 的属性会「钻过去」，见下表。）

prop 传的是**同一份数据**，不是拷贝：父组件一改，子组件里的 prop 立刻跟着变。

「改 prop」有两层，结果完全不同：

| 写法                      | 结果                                                                                               |
|---------------------------|----------------------------------------------------------------------------------------------------|
| `props.task = { ... }`    | 被 Vue 拦下并告警，值不变（Vue 3 原文：`Set operation on key "task" failed: target is readonly.`） |
| `props.task.title = '新'` | **真的改到了父组件的数据**——传进来的是同一个对象引用，Vue 不会告警                                 |

所以规矩是：**子组件要改数据，就 `emit` 给父组件，由父组件改**（下一节 ⑬ `defineEmits`）。

#### 怎么确认父组件的数据真的被改了？

「子组件说它改了父组件的数据」不能靠猜，得看得见。两种看法：

| 看法               | 怎么做                                    | 判断依据                                                  |
|--------------------|-------------------------------------------|-----------------------------------------------------------|
| 父组件自己渲染一份 | 父组件模板里写 `{{ selectedTask.title }}` | 子组件点一次「试试改 props.task.title」，父组件这行跟着变 |
| 看组件树           | 浏览器装 Vue Devtools，点父组件           | 父组件的 `task` 和子组件的 `task` 是同一份数据            |

示例用的是第一种：父组件自己也渲染了一遍
`{{ selectedTask.title }}`，子组件改完，父组件那行跟着变；而点「试试替换 props.task」时，两边都不变，控制台同时多出一条
readonly 告警。

原理就一句：**父子拿到的是同一个对象，不是两份拷贝**。所以子组件改
`props.task.title`，改的就是父组件 `selectedTask` 里那个 `title`；反过来父组件改，子组件也跟着变。

想在控制台里自己比对也行：父组件里 `console.log(selectedTask)` 会看到一个
`RefImpl`，它里面的值和子组件里 `console.log(props.task)` 打印出来的 `Proxy(Object)` 是同一个对象。

### 1.13 ⑬ `defineEmits`

> ▶️ **运行示例**：[打开 1.13 ⑬ defineEmits](http://localhost:5171/#/demos/1-13)
> · 源码：[`src/demos/DemoDefineEmits.vue`](../examples/01-template-syntax/src/demos/DemoDefineEmits.vue)

**子组件** `src/components/TaskItem.vue` —— 声明「我会发出哪些事件」：

```vue
<script setup lang="ts">
  const emit = defineEmits<{
    toggle: [id: number];
    remove: [id: number];
  }>();
</script>

<template>
  <input type="checkbox" @change="emit('toggle', id)"/>
  <button @click="emit('remove', id)">删除</button>
</template>
```

**父组件** `src/App.vue` —— 分别接住这两个事件：

```vue
<TaskItem @toggle="toggleTask" @remove="removeTask"/>
```

`[id: number]` 是具名元组，表示第一个参数是 `number` 类型的 `id`。`TaskItem`
声明了两个事件：勾选框发 `toggle`，删除按钮发 `remove`。

事件名和参数名**全靠名字对上**——写错不会编译报错，只是运行时收不到值。

### 1.14 ⑭ `ref`

> ▶️ **运行示例**：[打开 1.14 ⑭ ref](http://localhost:5171/#/demos/1-14)
> · 源码：[`src/demos/DemoRef.vue`](../examples/01-template-syntax/src/demos/DemoRef.vue)

```ts
const draft = ref('');
const tasks = ref<Task[]>([]);
```

| 位置 | 写法                |
|------|---------------------|
| 模板 | `draft`（自动解包） |
| 脚本 | `draft.value`       |

自动解包只对**顶层**的 ref 生效：嵌套在对象 / 数组里的 ref，模板里拿到的还是 ref 对象本身，得写
`.value`。

为什么脚本里要写 `.value`：`ref` 之所以是个对象，是为了在 JS 里也能跟踪变化（内部用 `.value`
存值并劫持 getter/setter）。模板由编译器生成，编译期就知道哪些是 ref，所以自动帮你解包；手写的 JS 没有这层信息，只能自己写
`.value`。

### 1.15 ⑮ `computed`

> ▶️ **运行示例**：[打开 1.15 ⑮ computed](http://localhost:5171/#/demos/1-15)
> · 源码：[`src/demos/DemoComputed.vue`](../examples/01-template-syntax/src/demos/DemoComputed.vue)

同一个「剩余未完成数」，两种写法：

```ts
// 写法一：computed —— 派生数据
const remaining = computed((): number => tasks.value.filter((task) => !task.done).length);

// 写法二：普通函数
const remainingByMethod = (): number => tasks.value.filter((task) => !task.done).length;
```

模板里：

```vue
<p>剩余 {{ remaining }} 项</p>            <!-- computed：模板自动解包 -->
<p>剩余 {{ remainingByMethod() }} 项</p> <!-- 函数：必须加括号调用 -->
```

**先说结论：两种写法在「会不会更新」上没有区别。** 函数写在模板里一样是响应式的——渲染时读到的
`tasks.value` 会被当前渲染 effect 收集成依赖，所以 `{{ remainingByMethod() }}` 同样会跟着 `tasks`
更新。差别在别的地方：

| 维度                   | `computed`                                 | 普通函数                                |
|------------------------|--------------------------------------------|-----------------------------------------|
| 模板写法               | `{{ remaining }}`（自动解包）              | `{{ remainingByMethod() }}`（必须调用） |
| 计算次数               | 依赖不变只算一次，多次读取共用同一份缓存   | 每次调用都重算，模板里读 N 次就算 N 次  |
| 依赖变了、但派生值没变 | 不惊动下游组件（值相等就短路）             | 下游照旧重渲染，函数白算一遍            |
| 它是「值」还是「动作」 | 值（ref）：可直接当 props / watch 源传出去 | 动作：传下去别人还得记得调用它          |
| 能不能反写回源         | 可写 computed 支持 `get` / `set`           | 不能                                    |
| 求值时机               | 惰性：没人读就不算                         | 惰性：没人调用就不算                    |

> 漏写括号的后果：`{{ remainingByMethod }}` 会把**函数源码当文本**渲染出来。

#### 配套示例里能直接看到差别

配套示例 `src/demos/DemoComputed.vue`（`src/App.vue`
里也有一份同样的对照）把两种写法并排放，各挂一个计数器：

```ts
let computedRuns = 0;
let methodRuns = 0;

const remaining = computed((): number => {
    computedRuns++;
    return tasks.value.filter((task) => !task.done).length;
});

const remainingByMethod = (): number => {
    methodRuns++;
    return tasks.value.filter((task) => !task.done).length;
};
```

打开页面后点「触发一次重渲染」按钮（它只改一个跟派生数据无关的状态），实测增量：

| 操作                                  | computed 实算 | 普通函数实算 |
|---------------------------------------|---------------|--------------|
| 首次挂载                              | +1            | +1           |
| 点「触发一次重渲染」（派生数据没变）  | **+0**        | **+1**       |
| 切换筛选条件 `filter`（派生数据没变） | **+0**        | **+1**       |
| 新增一条任务（剩余数 2 → 3）          | +1            | +1           |
| 勾选一条任务（剩余数 3 → 2）          | +1            | +1           |

规律很清楚：**只有依赖真的变了，`computed` 才重算；不管依赖变没变，普通函数每次被调用都重算。**

「依赖变了但派生值没变 → 下游不重渲染」这条短路，源码在 `@vue/reactivity` 的 `refreshComputed` 里：

```js
if (dep.version === 0 || hasChanged(value, computed._value)) {
    computed.flags |= 128;
    computed._value = value;
    dep.version++; // 只有值真的变了，才 bump 版本号惊动下游
}
```

> ⚠️ **计数器为什么用普通变量而不是 `ref`？**
>
> 因为在 `computed` 的 getter 里写 `ref` 会自触发递归，Vue 会直接报
> `Maximum recursive updates exceeded`（第 2 章细讲调度机制）。这也顺带说明：`computed`
> 的 getter 应该是纯粹的，正式代码里不要在 getter 里写状态。

#### 什么时候用哪个

- **派生数据**用 `computed`：昂贵且被多处读取、要当「值」传出去（props / `watch`
  源）、希望值没变时别惊动下游。
- **动作**用普通函数：带副作用（如 `addTask`）、要每次拿最新快照、根本不是派生数据（发请求、埋点）。

### 1.17 ⑰ 组件上的 `v-model` 与 `defineModel`

> ▶️ **运行示例**：[打开 1.17 ⑰ 组件 v-model 与 defineModel](http://localhost:5171/#/demos/1-17)
> · 源码：[`src/demos/DemoDefineModel.vue`](../examples/01-template-syntax/src/demos/DemoDefineModel.vue)

前置知识：⑫ `defineProps`、⑬ `defineEmits`、⑯ 组件的 props 绑定与事件监听。

组件上的 `v-model` 不是新机制，它就是 **「父传一个 prop + 子 emit 一个事件」**
的缩写。这节分四步拆开，最后用 `defineModel` 收回去。

> 步骤 1、2 用一个虚构的 `TitleInput` 组件做例子（**本项目里没有这个文件**），它比 `TaskFilterBar`
> 轻，只为把契约讲干净；步骤 4 再回到项目里真正用的 `TaskFilterBar`。

#### 步骤 1 · 父组件侧：`v-model` 展开成什么

```vue
<!-- 父组件 -->
<TitleInput v-model:title="pageTitle"/>
```

等价于：

```vue
<TitleInput :title="pageTitle" @update:title="pageTitle = $event"/>
```

规则只有一条：**`v-model` 后面的参数就是 prop 名，事件名是 `update:` + prop 名**。

| 写法                | prop 名      | 事件名              |
|---------------------|--------------|---------------------|
| `v-model="x"`       | `modelValue` | `update:modelValue` |
| `v-model:title="x"` | `title`      | `update:title`      |

编译器真实产物（`@vue/compiler-sfc` 实测）：

```
<Child v-model="x" />        →  modelValue: x,  "onUpdate:modelValue": $event => (x = $event)
<Child v-model:title="x" />  →  title: x,        "onUpdate:title": $event => (x = $event)
```

注意父组件这一侧**只需要 `v-bind`（④）和 `v-on`（⑤）**，没有新语法。

#### 步骤 2 · 子组件侧：手写这份契约

先不用 `defineModel`，用 ⑫ ⑬ 手写一遍：

```vue
<script setup lang="ts">
  const props = defineProps<{
    title: string;
  }>();

  const emit = defineEmits<{
    'update:title': [value: string];
  }>();
</script>

<template>
  <input
      :value="props.title"
      @input="emit('update:title', ($event.target as HTMLInputElement).value)"
  />
</template>
```

对照着看，契约就三件事：

| 位置     | 约定                                               |
|----------|----------------------------------------------------|
| prop 名  | 叫 `title`，父组件必须用 `:title` 传               |
| 事件名   | 叫 `update:title`，父组件必须用 `@update:title` 接 |
| 值往哪去 | 子组件 `emit`，父组件用 `$event` 接住并写回状态    |

参数名两边必须一致，写错不会编译报错，只是运行时收不到值——**没有魔法，全靠名字对上**。

一个组件可以有多个 model：

```vue
<script setup lang="ts">
  const title = defineModel<string>('title');
  const count = defineModel<number>('count');
</script>
```

```vue
<Child v-model:title="t" v-model:count="c"/>
```

#### 步骤 3 · `defineModel`：把上面两坨合成一行

`defineModel` 是 **Vue 3.4+** 的编译宏（本项目 Vue 3.5.44
✓），它把「声明 prop + 声明事件 + 维护一个双向 ref」打包成一行：

```vue
<script setup lang="ts">
  const title = defineModel<string>('title', {required: true});
</script>

<template>
  <input v-model="title" placeholder="标题"/>
</template>
```

编译器展开后（`@vue/compiler-sfc` 3.5 实测产物，省略 `__expose__` 等样板）：

```js
export default _defineComponent({
    props: {
        "title": {type: String, ...{required: true}},
        "titleModifiers": {},
    },
    emits: ["update:title"],
    setup(__props) {
        const title = _useModel(__props, 'title');
        return {title};
    },
});
```

和步骤 2 手写的那一坨一对就上了：`props` 自动生成、`emits` 自动生成、`title`
是个双向 ref——**读它 = 读 prop，写它 = emit 事件**。

几个容易卡住的点：

- **第一个参数就是 prop 名**，也就是事件名的后半段：`defineModel('title')` ↔ 父组件写
  `v-model:title`。
- **`{required: true}` 落在 props 声明上**（上面产物里的
  `...{required: true}`），它就是普通 prop 的必填声明，跟 ⑫ 里写 `defineProps` 时的 `required`
  一模一样：
    - 运行时：父组件没传会告警 `[Vue warn]: Missing required prop: "title"`；
    - 类型上：`defineModel<T>()` 的类型是 `T | undefined`，加上 `required: true` 后收窄成
      `T`，模板里比较时不用写 `!`。
- **泛型不保证运行时校验**：`defineModel<string>('title')` 编译出
  `type: String`，运行时能校验；`defineModel<TaskFilter>()` 编译出
  `type: null`——TS 类型在编译期被擦除，自定义类型运行时校验不了，只能靠 TS 编译器。
- **`required` 和 `default` 二选一**：要么父组件必须传，要么子组件给兜底值。

#### 步骤 4 · 回到项目里真正用的那个

`src/components/TaskFilterBar.vue`：

```vue
<script setup lang="ts">
  import type {TaskFilter} from '@/types';

  const filter = defineModel<TaskFilter>({required: true});
</script>
```

父组件 `src/App.vue`：

```vue
<TaskFilterBar v-model="filter"/>
```

- 没传名字 → prop 名用默认的 `modelValue`，事件名就是 `update:modelValue`。
- 变量名 `filter` 和 prop 名 `modelValue` **毫无关系**。父组件 `v-model="filter"` 右边的 `filter`
  是**父组件自己的变量名**；子组件里的 `filter` 也是它自己的变量名。三个名字可以各不相同，`v-model`
  负责把它们连起来。
- `@click="filter = option.value"` → 赋值 → 自动 emit `update:modelValue` → 父组件的 `filter`
  更新 → 作为 prop 传回 → 按钮高亮切换。

> **受控语义提醒**：子组件里的 `filter` 说了算吗？**不算**。
>
> 绑了 `v-model` 时，`useModel`
> 内部不会直接改本地值，而是先把新值 emit 出去，等父组件把新的 prop 传回来才生效。所以父组件如果收到了
> `update:modelValue`
> 却**拒绝更新状态**（比如做了校验拦下来），子组件的值会**保持不变**——这是「受控组件」的标准行为。反过来，如果父组件压根没绑
> `v-model`，`useModel` 会退化成**本地模式**：子组件自己改自己的值，父组件收不到任何通知。

#### 手写版 vs `defineModel`（小结）

| 维度         | 手写（⑫ + ⑬）         | `defineModel`（3.4+） |
|--------------|-----------------------|-----------------------|
| prop 声明    | 要自己写              | 自动                  |
| 事件声明     | 要自己写              | 自动                  |
| 双向 ref     | 自己 `ref` + 手动同步 | 自动（`useModel`）    |
| 模板写法     | `:value` + `@input`   | 直接 `v-model`        |
| Vue 版本要求 | 3.0+                  | 3.4+                  |

老项目、组件库里手写版仍是主流（不挑 Vue 版本）；新项目直接上 `defineModel`。

## §3 代码精读

### 3.1 `src/App.vue`

```ts
import {computed, ref} from 'vue';                          // ① ②
import TaskFilterBar from '@/components/TaskFilterBar.vue';    // ②
import TaskItem from '@/components/TaskItem.vue';
import type {Task, TaskFilter} from '@/types';

const draft = ref('');                          // ⑭
const filter = ref<TaskFilter>('all');          // ⑭ ⑰
const tasks = ref<Task[]>([                     // ⑭
    {id: 1, title: '读 Vue 3 响应式源码', done: true},
    {id: 2, title: '手写一个最小 createReactive', done: false},
    {id: 3, title: '给待办列表加筛选与统计', done: false},
]);
```

`ref` 的三条规则：模板里写 `draft`，脚本里写 `draft.value`。

```ts
// 第 2 章会拆开讲 computed 的缓存机制，这里先让它跑起来
const visibleTasks = computed((): Task[] => {   // ⑮ ⑰
    if (filter.value === 'active') return tasks.value.filter((task) => !task.done);
    if (filter.value === 'done') return tasks.value.filter((task) => task.done);
    return tasks.value;
});
```

`computed` 依赖 `filter` 和 `tasks`，两者不变时直接返回缓存值。

```ts
// ⑮ 计数器用普通变量而不是 ref：在 computed 里写 ref 会自触发递归，报 Maximum recursive updates exceeded
let computedRuns = 0;
let methodRuns = 0;

// ⑮ 无关状态：只用来制造一次重渲染，不影响任何派生数据
const renderTick = ref(0);

// ⑮ 写法一：computed —— 依赖不变就返回缓存，不重复计算
const remaining = computed((): number => {
    computedRuns++;
    return tasks.value.filter((task) => !task.done).length;
});

// ⑮ 写法二：普通函数 —— 每次被调用都重新算一遍
const remainingByMethod = (): number => {
    methodRuns++;
    return tasks.value.filter((task) => !task.done).length;
};

// ⑮ 触发一次与派生数据无关的重渲染，用来观察两个计数器
const triggerRerender = (): void => {
    renderTick.value++;
};
```

⑮ 对照实验：两种写法算出同一个数字，但 `computed`
只在依赖变化时重算，普通函数每次调用都重算。计数器故意用普通变量——在 `computed` 的 getter 里写 `ref`
会自触发递归，报Maximum recursive updates exceeded。

```ts
const addTask = (): void => {                    // ⑰
    const title = draft.value.trim();              // ⑭
    if (!title) return;
    tasks.value.unshift({id: Date.now(), title, done: false});
    draft.value = '';
};

const toggleTask = (id: number): void => {        // ⑰
    const task = tasks.value.find((item) => item.id === id);
    if (task) task.done = !task.done;
};

const removeTask = (id: number): void => {
    tasks.value = tasks.value.filter((item) => item.id !== id);
};
```

`unshift` 原地修改数组、`task.done = ...` 修改对象属性，Vue 都能感知（深层响应式，第 02 章细讲）。

> `Date.now()` 当 id 有同毫秒碰撞风险，正式项目用自增计数器或 `crypto.randomUUID()`。

### 3.2 `src/components/TaskItem.vue`

```vue
<script setup lang="ts">
  import type {Task} from '@/types';

  const props = defineProps<{        // ⑫
    task: Task;
  }>();

  const emit = defineEmits<{         // ⑬
    toggle: [id: number];
    remove: [id: number];
  }>();
</script>

<template>
  <li class="task" :class="{ 'task--done': props.task.done }">   <!-- ⑪ -->
    <label class="task__main">
      <input type="checkbox" :checked="props.task.done" @change="emit('toggle', props.task.id)"/>
      <span class="task__title">{{ props.task.title }}</span>   <!-- ③ -->
    </label>
    <button class="task__remove" type="button" @click="emit('remove', props.task.id)">删除</button>
  </li>
</template>
```

checkbox 用 `:checked` + `@change` 而不是 `v-model`：props 不可修改，交给父组件改。`emit`
是顶层变量，模板里直接用（②）。

### 3.3 `src/components/TaskFilterBar.vue`

```vue
<script setup lang="ts">
  import type {TaskFilter} from '@/types';

  // defineModel：Vue 3.4+ 的编译宏。
  // 没传第一个参数 → prop 名用默认的 modelValue，事件名是 update:modelValue；
  // 变量名 filter 随便起，和 prop 名无关（父组件写 v-model="filter" 时，右边的
  // filter 是父组件自己的变量名）。展开细节见 docs/01 的 1.17 ⑰。
  const filter = defineModel<TaskFilter>({required: true});   // ⑰

  const options: { value: TaskFilter; label: string }[] = [
    {value: 'all', label: '全部'},
    {value: 'active', label: '未完成'},
    {value: 'done', label: '已完成'},
  ];
</script>

<template>
  <div class="filters">
    <button
        v-for="option in options"                                  <!-- ⑦ -->
    :key="option.value"                                        <!-- ⑧ -->
    class="filters__item"
    :class="{ 'filters__item--active': filter === option.value }"  <!-- ⑪ -->
    type="button"
    @click="filter = option.value"                             <!-- ⑤ ⑰ -->
    >
    {{ option.label }}                                         <!-- ③ -->
    </button>
  </div>
</template>
```

`filter = option.value` → 自动 emit `update:modelValue` → 父组件的 `filter`
更新 → 作为 prop 传回 → 按钮高亮切换。

注意这里子组件的值**不是自己说了算**：绑了 `v-model` 时，`useModel`
不会直接改本地值，而是 emit 出去等父组件把新 prop 传回来。父组件若拒绝更新状态，子组件的值就保持不变（受控组件，详见 ⑰）。
